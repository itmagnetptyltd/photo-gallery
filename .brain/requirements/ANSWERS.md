## 1. Does "gallery" mean the whole application, or one named collection of Photos inside it?

Gallery means the whole application and its single collection of Photos. There are no named collections or multiple galleries.

## 2. Is there any concept of an Owner or of signing in at all, or is every Photo visible to anyone who can reach the application?

There is no Owner concept and no sign-in. The application is local and every Photo is visible to anyone who can reach the application.

## 3. Is the application only ever used by one person on one PC, or must it serve several people at the same time?

The application is intended for use on one local development PC by one person. Multi-user concurrent access is out of scope.

## 4. Does "photo" cover still images only, and which file formats must be accepted?

Photo means still images only. Accept JPEG and PNG files.

## 5. What is the largest file a person may upload, and what must they see when they exceed it?

The maximum upload size is 10 MB per Photo. If the file exceeds the limit, reject it and show a clear message in the upload modal.

## 6. What must happen when a person chooses a file that is not an accepted image, and must that be detected before the file is transferred?

Only accepted image files are allowed. Validate the selected file in the browser and validate it again on the server using the file content/type. Reject invalid files with a clear error message.

## 7. May more than one Photo be uploaded in a single use of the modal?

Only one Photo may be selected and uploaded per use of the modal.

## 8. May an Upload in progress be cancelled, and what must happen if the modal is closed before the Upload completes?

An Upload cannot be cancelled once it has started. Closing the modal while an Upload is in progress is disabled until the Upload completes or fails.

## 9. What must the person see when an Upload fails part-way, and must a failed Upload leave nothing behind?

If an Upload fails, show a clear error message and allow the person to retry. A failed Upload must leave no Photo record and no partial file behind.

## 10. Are two Uploads of the same image file two Photos or one?

Every Upload creates a new Photo. Uploading the same image file twice creates two Photos.

## 11. Must the Original be retained unchanged after Upload, and must anyone be able to retrieve it?

The Original is retained unchanged after Upload. The application does not provide a separate download feature; the Original is used when the Photo is opened in the larger view.

## 12. Is the thumbnail a separate smaller Rendition produced by the system, or the Original delivered whole and shown at a reduced size?

The thumbnail is a separate smaller Rendition generated by the application. The grid uses the thumbnail rather than loading the full Original.

## 13. What information about a Photo, if any, must be shown beside it in the grid or in the larger view?

No additional Photo information is required in the grid or larger view. Show the image only.

## 14. In what order must Photos appear in the grid, and when the client says "date" do they mean Capture date or Upload date?

Photos appear newest Upload first. The ordering is based on Upload date/time, not Capture date.

## 15. What must happen when there are more Photos than fit on one screen — does "all uploaded photos" still mean all of them at 10,000?

Photos are displayed using pagination or incremental loading rather than requiring thousands of Photos to be rendered at once. The application must support the available local storage without a fixed small gallery-size limit.

## 16. What must the home page show when no Photo has been uploaded yet?

When no Photo has been uploaded, show an empty-state message inviting the person to upload a Photo, together with the Upload Photo control.

## 17. Must an existing Photo ever be removed or renamed by anyone, and if it is removed, is it recoverable?

Existing Photos may be removed. The delete action is available from the Photo tile/grid, requires confirmation, and permanently removes the Photo and its stored files. Renaming is not supported.

## 18. Does "immediately displayed" apply only to the person who uploaded the Photo, or must an already-open grid belonging to someone else update too?

Immediately displayed means the Photo uploaded by the person is added to that person's currently open grid without requiring a full page reload. Live updates to other already-open grids are out of scope.

## 19. What does "a larger view" mean — an overlay on the home page or a separate page — and at what resolution is the Photo shown?

The larger view is an overlay/modal on the home page. It displays the Photo at a size that fits the available viewport while allowing the person to see the image properly; it does not navigate to a separate Photo page.

## 20. Must the larger view offer navigation to the next and previous Photo, and how must it be dismissed?

The larger view supports previous and next Photo navigation. It is dismissed with a close control, and the Escape key may also close it.

## 21. Which devices, browsers and viewport widths must the interface support?

The application must support desktop development PCs using current Chrome, Edge, and Firefox browsers. The layout must reflow for common desktop viewport sizes; mobile phones and tablets are out of scope.

## 22. What must be operable without a mouse, and against which accessibility standard, if any, will the interface be judged?

All primary actions must be keyboard operable, including tabbing to controls, opening a Photo with Enter, and closing the larger view with Escape. A formal WCAG conformance level is not required.

## 23. Who decides whether the interface is "clean", "attractive" and "user-friendly", and what evidence would make it acceptable or unacceptable?

The delivery team will use a simple modern visual design as the acceptance baseline: consistent spacing, clear controls, readable text, responsive grid reflow, and no unnecessary visual clutter. The client can accept or request changes during the demo.

## 24. Must uploaded Photos still be in the Gallery after the application is stopped and started again?

Uploaded Photos must persist after the application and PC are stopped and started again. Photos are stored on disk and their metadata is stored in SQLite.

## 25. Is there a limit on total storage, and what must happen when it is reached?

There is no application-level total storage quota. Uploads continue until the available local disk space is exhausted; a disk-full condition must fail cleanly without leaving a partial Photo.

## 26. What counts as an "unnecessary" dependency, and who approves the dependency list?

Avoid unnecessary dependencies means do not add libraries unless they provide functionality that is not reasonably available from Node.js or the application code. A small number of established dependencies needed for the web server, SQLite access, and image thumbnail generation are acceptable.

## 27. Which Node.js versions and which operating systems must the application run on?

Use a current Node.js LTS release on Windows for the local development PC. Other operating systems are out of scope.

## 28. What does "easy to run on a local development PC" mean in checkable terms — how many steps, and what may a person be expected to install first?

Easy to run means Node.js must be installed first, then the project can be started with the documented install and run commands. No database server, cloud service, Docker, or other external infrastructure is required.
